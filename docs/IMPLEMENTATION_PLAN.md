# HealthMonitor — план реализации MVP

Источники ТЗ: `docs/HealthMonitor_Устав проекта.docx` (устав), `docs/WBS диаграмма.png` (WBS, задачи KAN-*),
`docs/Презентация HealthMonitor.pdf` (презентация устава). Ниже — сведённый перечень требований,
архитектура, декомпозиция задач, критерии готовности и зависимости.

## 1. Архитектура и стек (решение Tech Lead, KAN-18)

| Слой | Технология | Обоснование |
|---|---|---|
| Backend | Node.js 24 + Express 5, `node:sqlite` | Один рантайм с фронтендом; SQLite встроен в Node — без внешних сервисов, легко заменить на PostgreSQL через слой `db/` (масштабируемость ×5) |
| Криптография | `node:crypto`: scrypt (пароли), AES-256-GCM (поля ПДн/медданных), HMAC-SHA256 (JWT, индексы поиска) | 152-ФЗ: шифрование при хранении; без сторонних крипто-библиотек |
| Аутентификация | JWT (access, 1 ч) + 2FA по SMS-коду | KAN-22, KAN-23 |
| Уведомления | Абстракция провайдеров `push`, `sms` (SMS-шлюз) — в dev/test пишут в таблицу `notifications` (outbox) | KAN-40/41/42; реальный шлюз подключается конфигом |
| Устройства | Слой адаптеров (`integrations/adapters/*`): глюкометр, тонометр, Google Health API-формат | KAN-33..37 |
| Фоновые задачи | Встроенный планировщик (`setInterval`): эскалация алертов, напоминания | KAN-39, напоминания |
| Frontend | React 19 + Vite + react-router; графики на собственном SVG | KAN-20, адаптивная вёрстка (KAN-55) |
| Тесты | `node --test` (backend, интеграционные через HTTP), Vitest (frontend), ESLint | KAN-14 |
| CI/CD | GitHub Actions (`.github/workflows/ci.yml`), Dockerfile + docker-compose | KAN-13 |

Масштабируемость: stateless API (JWT), все данные в БД, планировщик идемпотентен; БД за слоем репозитория.
HIPAA-готовность: шифрование полей, аудит, журнал доступа к медданным, RBAC, разделение ключей (`HM_ENC_KEY`).
Локализация в РФ: конфиг `DATA_REGION=ru`, сервер отказывается стартовать в production при другом значении; трансграничная передача запрещена (нет внешних вызовов кроме шлюзов из allow-list).
