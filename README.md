# HealthMonitor

MVP телемедицинской платформы удалённого мониторинга пациентов с сахарным диабетом 2 типа, артериальной
гипертонией и бронхиальной астмой. Требования — в `docs/` (устав, WBS, презентация); план и статус —
`docs/IMPLEMENTATION_PLAN.md`, `docs/PROGRESS.md`; меры по 152-ФЗ — `docs/COMPLIANCE_152FZ.md`.

## Возможности
- **Пациент**: ручной ввод глюкозы, АД/пульса, ПСВ; история и графики; напоминания о лекарствах и измерениях;
  привязка глюкометра/тонометра; чат с врачом; контакты родственников и приглашения; согласия; отчёт PDF; 2FA.
- **Врач**: дашборд всех пациентов с приоритизацией по критичности; лента алертов с подтверждением; карточка
  пациента; индивидуальные пороги; отчёт PDF; чат; заявки пациентов.
- **Алерты**: пороги по умолчанию и индивидуальные; push + SMS врачу; эскалация через 15 и 30 минут без реакции
  (администраторы, родственники); экстренные SMS родственникам.
- **Родственник**: просмотр показателей и алертов подопечного (только чтение).
- **Администратор**: пользователи, роли (RBAC), блокировка, модерация заявок, аудит, журнал доступа к медданным,
  версии согласий, зашифрованные резервные копии, метрики критериев успеха устава.
- **Устройства**: слой адаптеров `glucometer-v1`, `tonometer-v1`, `health-connect` (Google Health Connect).

## Стек
Node.js 24 (Express 5, встроенный `node:sqlite`, `node:crypto`), React 19 + Vite + React Router, pdfmake.

## Быстрый старт (разработка)
```bash
cd backend && npm install && npm run seed && npm run dev      # API на :4000, пилотные данные
cd frontend && npm install && npm run dev                     # веб-клиент на :5173 (прокси /api → :4000)
```
Пилотные учётные записи (синтетические данные): `admin@healthmonitor.local`, `doctor1..5@healthmonitor.local`,
`patient1..20@healthmonitor.local`. Пароль задаётся переменной `HM_SEED_PASSWORD`; если её нет, `npm run seed`
генерирует случайный пароль и показывает его один раз. В режиме разработки SMS не отправляются: коды 2FA подставляются в форму.

Симуляция устройства (ключи печатает `npm run seed`):
```bash
cd backend && node scripts/simulate-devices.js --adapter glucometer-v1 --serial GL100-PILOT-01 --key <ключ> --critical
```

## Тесты
```bash
cd backend && npm test          # node:test: модульные, интеграционные (HTTP), e2e-сценарий пилота, нагрузка ×5
cd frontend && npm run lint && npm test && npm run build
```

## Развёртывание (сервер в РФ)
```bash
cp .env.example .env            # сгенерировать ключи, указать домен и первого администратора
docker compose up -d --build    # API + веб-клиент в одном образе, TLS на Caddy, ежедневный бэкап
```
Резервная копия: `npm run backup` или кнопка в админ-панели. Восстановление (API остановлен):
`npm run restore -- <файл> --yes` — текущая БД сохраняется рядом.

CI: `.github/workflows/ci.yml` — тесты backend, lint/тесты/сборка frontend, сборка Docker-образа.

## Конфигурация
| Переменная | Назначение |
|---|---|
| `HM_ENC_KEY`, `HM_INDEX_KEY`, `HM_JWT_SECRET` | 32-байтные ключи (hex/base64); обязательны в production |
| `DATA_REGION` | должно быть `ru` (152-ФЗ) |
| `HM_DB_FILE`, `HM_BACKUP_DIR`, `HM_BACKUP_DAILY` | БД, каталог и ежедневное резервное копирование |
| `HM_SMS_PROVIDER` (`outbox`/`http`), `HM_SMS_GATEWAY_URL` | SMS-шлюз |
| `HM_ESCALATION_MINUTES` | шаг эскалации (SLA 15 мин) |
| `HM_STATIC_DIR` | каталог собранного веб-клиента |
| `HM_ADMIN_EMAIL`, `HM_ADMIN_PASSWORD` | создание первого администратора |
